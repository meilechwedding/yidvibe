## Maintenance map

| What to change | Home | Boundaries |
| --- | --- | --- |
| Colors | `src/styles/palette.json` | Single source for CSS, browser theme metadata and rendered social/icon colors |
| Generated palette CSS | `src/styles/palette.css` | Generated by `npm run theme:sync`; do not edit directly |
| Typography, spacing, semantic colors, radii and motion | `src/styles/theme.css` | Semantic aliases reference canonical palette tokens |
| Global component classes | `src/app/globals.css` | Imports theme; no repeated palette literals |
| Shared primitives and composed product UI | `src/components/ui`, `src/components/brand` | Radix primitives vs brand-aware forms/cards/layout; feature UI stays in feature folders |
| Appearance helpers and brand identity | `src/lib/design` | Accent maps, form control classes, serialized image colors, shared approved vector path |
| Identity and navigation/tool catalogs | `src/config` | Public constants and option definitions, not privileged feature-management logic |
| Text and copy | `src/content/pages`, `src/content/forms`, `src/content/common.ts`, `src/content/interactions.ts` | Metadata, page headers, form labels/help/actions and shared interaction wording; rich instructional JSX and dynamic/user content remain with renderers |
| Interaction behavior | `src/hooks`, `src/hooks/navigation` | Error focus, unsaved-change lifecycle, safe app history and draft navigation |
| Pure business functions | `src/lib/domain` | Calendar grouping, contact links, competition status and budget overlap; safe for client/server imports |
| Media formatting | `src/lib/media` | Screenshot URL construction; no transport or storage calls |
| Next.js entry points | `src/app` | Route/layout/metadata filenames stay in their required locations |
| Existing server functions | `src/lib/actions` and existing server-only `src/lib` modules | Left in place and outside database/backend implementation review |

`src/lib/site.ts` is a necessary compatibility export surface for existing imports, including excluded server code. It owns no definitions or behavior. Old duplicate navigation/calendar/competition helper files were removed after their consumers/tests moved to the new homes. No route wrappers or mass file moves were introduced.

Palette synchronization runs before dev/build. `npm run theme:check` detects drift. CSS and serialized metadata share JSON values, so editing a color does not require separate social-image, favicon-renderer, manifest or viewport edits. Static public brand assets were preserved.

## Additional source defects fixed

- A private project's builder profile could be advertised as a contact route. Existing profile visibility now determines whether contact values/actions appear; private profiles receive explanatory copy. No privacy/publication settings were changed.
- Profile metadata could expose a private name/bio before body visibility checks. Private metadata is now generic.
- Profile tool/skill links pointed to Directory, whose filters do not support them. Links now target Builders.
- Auth, project, profile, report, upload and message fields lacked names/error associations or selected state in specific paths. Labels, ARIA error/required/selection state, announcements and autocomplete were repaired.
- IME composition Enter could send a message. Composition and Shift+Enter remain text-entry gestures; blank messages are rejected locally.
- Thrown upload errors could leave controls without useful feedback. Image, gallery and cover/avatar paths recover and clear busy state with mocked regression coverage.
- Native share failures were treated as cancellation. Real failures fall back to copy; user cancellation does not. Timers are cleaned up.
- Offscreen carousel cards remained keyboard reachable. Inactive slides are inert/hidden; focus and hover independently pause rotation, and reduced motion suppresses slide transitions.
- The secondary board filter shell retained a manual mobile dialog. It now has a named Radix portal, Escape/focus handling and bounded viewport scrolling.
- Save/follow controls allowed duplicate pending toggles. Pending controls are disabled.
- Cancel trusted unrelated browser history. It now uses the shared safe app-history fallback.
- Anonymous-voting docs contradicted the actual signed-out login gate. Docs now explain the existing account requirement; authentication behavior was not changed.
- Some small orange/sage/gold text pairs missed contrast requirements. Existing deeper palette tones or ink supply selected corrected pairs. Numeric contrast tests cover those pairs, not all site color combinations.
- Long hero titles, builder status rows and gig messages now wrap. Cards expose keyboard focus; avatar/status controls have meaningful names.
- Visual marquee clones no longer duplicate keyboard/screen-reader navigation. Focus pauses the marquee. Shared dialog close controls have 44px targets.

The review preserved stored data, taxonomy, feature flags, assets and existing budgets/date semantics. It did not redesign the product without rendered evidence.

## Publication boundary

The user authorized commit and push to a dedicated branch. Main is not merged or overwritten; no force push or deployment command is used. Remote main is rechecked before publication. The final response verifies the exact remote branch SHA and reports registered statuses/check runs for that SHA, including any pending or blocked check rather than treating a local build as remote CI success.
